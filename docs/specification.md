# Specification and assumptions

The only production destinations are Governance `rrkah-fqaaa-aaaaa-aaaaq-cai` and ICP Ledger `ryjl3-tyaaa-aaaaa-aaaba-cai`; Management `canister_info` reads inspect exact controller principals returned by Governance. Ledger archive destinations come exclusively from validated replicated Ledger responses. An Index is not used in production reconciliation.

D-QUORUM is neuron `4713806069430754115`. Its controller must equal the separately reviewed install argument before any target write. Governance's controller set must be exactly NNS Root `r7inp-6aaaa-aaaaa-aaabq-cai`. The target must retain this canister as a hotkey. These checks reject substitution rather than adopting a different identity. Observe-only inspection does not grant authority.

The evaluator is vendored unchanged at Dendrite commit `b9bacd5e97eded6b5bcb0ad37d0a30b8a4ecb291`, including its exact parity fixture and Apache licence. It contains 23 direct rules, with multiple topic evaluations. Its internal NNS policy source is `d55a0f4d4edfabe49d8fd543aff473084cb741f2`; protocol adapters and monetary tests use `83f29e0803496ba6aaea3d6b43f6c6bebea12dd9`. These are intentionally distinct. Protocol constants are not operator policy overrides.

Candidates come only from bounded `list_known_neurons`. IDs, metadata lengths, duplicates and the complete response are validated. Each candidate has a resumable evidence collection: target full public configuration, exact metadata, bounded dependency batches, dependency metadata, and replicated Management controller evidence. Only the pinned evaluator's `Compliant` result admits a candidate. Structural committed numeric topics determine topic eligibility, intersected with the 16 ordinary topics supported by the protocol pin. Approved singleton defaults do not establish commitment. All raw manager IDs are retained by the evaluator before a disjointness set is constructed. Temporary collection failures retry or fail the round; they never become zero scores or conclusive eligibility. Human principals are not inspected as canisters; missing controller evidence is not invented.

Following maps retain raw vector lengths until validation; duplicate topic keys fail. Scoring deduplicates followee IDs after the 15-entry raw bound. Unknown visibility values and contradictory stake, voting-power or identity observations fail. A known-neuron name is never a substitute for configuration. Metadata observations must match identity and remain within 300 seconds of the corresponding target snapshot. The evaluator's activity clock is Governance's retrieval timestamp.

Support scanning uses `get_neuron_index`'s exclusive ascending neuron-ID cursor. Every nonempty page must strictly progress; an empty page proves pagination completion. Pages contain at most 100 records. IDs select full-neuron reads in batches of 50, with public inclusion enabled and caller-readable enumeration disabled. Explicit visibility must be Public (2); private records are ignored even if a privileged read returns them. Missing full configuration for an index-public neuron fails unless a later observation conclusively shows deletion or private visibility. VP and following are taken together from each full-neuron response; index VP is never used. Each full batch commits its scores and cursor together, so retries and upgrades cannot count it twice.

This is a bounded interval of observations, not an atomic NNS snapshot. Index membership and later full configuration can differ due to intervening changes. The full response is authoritative for support at that observation. New IDs below an already passed cursor may wait until the next weekly round. A round expires after three days. No partial round supplies an applied roster.

For each ordinary topic, a public follower's deciding VP, provided its validated dissolve state meets the observed ordinary-ballot voting threshold, is divided by the count of **all distinct effective followees**, including ineligible IDs. Each direct eligible non-self followee receives that fraction. Contributions are exact `u128` multiples of `360360 / count`, with checked accumulation; no floating point or per-contribution rounding is used. CatchAll (0) and Neuron Management (1) are not elected topics. Governance (4) and SNS/community fund (14) have no CatchAll fallback. Other topics use CatchAll only when their topic key is absent; an explicitly empty vector remains empty. The NNS setters normally remove empty keys. Scores are public direct support, not NNS threshold-ballot simulation.

The first candidate excludes D-QUORUM and the canister-owned proposer neuron as support sources. The deterministic proposer staking-account/controller binding also excludes it before bootstrap records its numeric ID. This is an explicit anti-feedback policy choice. It does not infer human ownership.

The regression `12000 -> X`, `9000 -> X,Y,Z`, `8000 -> X,Y` gives X exactly `19000`, including when Z is ineligible. A single candidate's self-following adds zero; the self ID still belongs to the denominator when evaluating its other followees.

Selection sorts positive-score, compliant topic-eligible candidates by descending exact score, then ascending numeric ID. A candidate conflicts only with already accepted candidates' complete manager sets. With A>B>C, A/B sharing manager m1, B/C sharing m2, and A/C disjoint, selection accepts A,C and rejects B. A lower-ranked manager-copying candidate cannot disqualify A. Exclusion records identify the selected conflict and shared IDs; they do not establish independent human ownership. Empty and short rosters are valid. There are no preferred seats, overrides or configurable ranking weights.

`set_delegates_per_topic(nat8)` accepts only the actual fixed Governance caller, including rejecting controllers and anonymous callers. Counts must be 1..15. Every accepted call advances a durable configuration revision and invalidates unfinished selection and new payout drafts. A dispatched old following intent remains available for readback, with no old-revision retry. Existing financial plans remain immutable.

Before application, every selected candidate is recollected and compared for compliance, manager sets and topic eligibility. A bounded traversal of all effective downstream voting dependencies must prove no route back to D-QUORUM. Private/unavailable dependencies or more than 4096 visited IDs per topic prevent application. A proof and validation older than 30 minutes cannot authorize a write. Concurrent NNS changes remain a non-atomic observation limitation.

The target's CatchAll must already be empty. The automation **does not clear it automatically**; a separately authorised controller/NNS action is an activation prerequisite. Therefore clearing an ordinary selection cannot silently restore a default through CatchAll. Selection never writes topic 1. The protocol's atomic `SetFollowing` writes only changed ordinary topics, with the intended complete map and original managers persisted first. Every response is followed by a new target read. A lost reply cannot lead to retry before readback. Only a fully matching readback publishes `Applied`; reward planning additionally requires its configuration revision to be current and the underlying support and candidate observations to be no more than eight days old; readback time does not renew them. Five failed transient selection attempts retain the last applied roster and fail the draft round.

The proposer bootstrap uses a fixed nonce `0x4451554f52554d31`, with staking subaccount SHA-256 of `0x0c || "neuron-stake" || canister principal || nonce_be`. This derivation is exclusively for this canister's new proposer. Recipient staking subaccounts are never derived from numeric IDs. Separately funded bootstrap ICP remains in that Governance staking account. `ClaimOrRefresh` is deterministic for this account; returned ID, controller and exact subaccount are verified before recording readiness. Manager-topic following on the proposer must be empty so it cannot automatically approve unrelated management proposals. Missing target manager membership or hotkey authority is a waiting condition. A daily live maintenance check may refresh D-QUORUM voting power through its hotkey; it cannot change management following.

The separate maturity job checks owned proposer binding, manager membership, proposal fee, a full minimum-stake reserve beyond the fee, available unstaked maturity and current in-flight disbursements. The conservative initial minimum requires at least one ICP after a 5% modulation reserve, stricter than the source's one-ICP pre-modulation minimum. Authorised proposal history is paginated before submission; matching open/adopted destination/actions block another proposal. At most one local unresolved attempt exists. A durable operation marker and hash bind proposer, managed target, action, 100%, and explicit destination owner=this canister/subaccount=None. The fixed URL uses `https://forum.dfinity.org`, which passed the reviewed source's domain restriction; it is not a claim that a particular forum discussion exists.

The proposer submits a Neuron Management proposal concerning D-QUORUM's maturity. It does not directly disburse either neuron's maturity. NNS records the proposer's proposal vote; other managers control majority adoption. A MakeProposal timeout or unexpected reply preserves the intent and investigates authorised history with exact proposer/action/destination/marker matching. No history match is not proof of no submission; exhausted history remains ambiguous, without resubmission. Unknown protocol actions/statuses fail safely. Known rejection/failure permits a later bounded-backoff attempt. Creation, adoption, execution and receipt are distinct states. The percentage applies to available maturity at execution. Governance delays finalization seven days and applies actual modulation.

Maturity execution, termination and receipt attribution are separate facts. An exact durable Executed proposal (including its execution timestamp when observed) proves successful initiation, not finalization. Recovery reads the target's progress list. A nonempty or unavailable list holds the operation. When empty, it invokes the supported existing-neuron ClaimOrRefresh command as a shared-neuron lock barrier, then obtains another fresh empty progress list with unchanged protected configuration, all within 300 seconds. Under the pinned executable contract this establishes terminal execution even when the entire seven-day transient progress interval was missed. An in-flight mint holds that lock; a failed mint restores progress before unlocking, or retains the lock when restoration fails. Neither an empty list alone nor elapsed time proves termination.

Only this barrier uses a restricted adapter preserving the typed ClaimOrRefresh result. Exact expected-ID success or the reviewed post-lock InsufficientFunds enum value 14 establishes the barrier. Every other variant, code, wrong/missing ID, absent/malformed reply or transport uncertainty leaves the operation unresolved. Error-message text is never evidence. Ordinary Governance `manage` still rejects all errors; no refresh-maintenance success is inferred from error 14. This correction changes neither stable V3 nor public Candid.

`TerminalExecutionVerified` records this terminal observation separately from execution time. A later distinct cycle still waits the normal proposal cadence and fresh full preflight, including no conflicting pending disbursement. Bound Open/Adopted proposals with unavailable history remain unresolved. Previously verified Executed/AwaitingFinalization phases, including historical V2 phases without an execution timestamp, retain their durable execution proof; migration never invents a timestamp. Uncertain creation is never resubmitted.

No pinned Ledger mint carries the proposal marker, fingerprint or a disbursement identifier. After missing transient observations, attributing a particular mint to this proposal is generally unprovable. Recovery leaves receipt attribution unresolved and does not select an arbitrary matching deposit or mint. Legacy tentative receipt observations remain historical. The independent payout job recognises only actual authoritative Ledger balances; a terminal proposal creates no spendable accounting balance.

Reward planning snapshots distinct recipients in the latest valid fully applied roster. Each full public neuron read must bind the ID to its actual 32-byte Governance staking subaccount, and all accounts must be unique. No caller supplies destinations. Unavailable/conflicting destinations prevent a new plan. A transfer increases that staking account's Ledger balance; it does not automatically refresh Governance's cached stake. Production separately refreshes existing public recipients with the supported `ClaimOrRefresh(NeuronIdOrSubaccount)` path and verifies protected following, controller and dissolve settings. Maintenance failure is separately visible and never resends confirmed ICP. As soon as all transfers are authoritatively confirmed the plan retires financially, releases only settled reservations, and starts its normal one-day admission delay. New rosters or deposits cannot shorten that delay. Unfinished maintenance stays in the existing completed-plan history, independent of the payment job; no uncertain transfer can enter that history.

A fifth existing-style timer job performs one maintenance item at a time, choosing the earliest due item with deterministic plan/recipient ties. It persists a retry reservation before awaiting, so a failed or delayed first recipient cannot starve later recipients. Retries back off from one hour to one day, with at most eight attempts. Success is terminal Complete; exhausted work is explicitly Abandoned, never financially failed or claimed successful. Original neuron/subaccount binding and protected configuration are checked. The existing 32-completed-plan retention bound remains; eviction counts every unfinished maintenance item in `pruned_unfinished_refreshes`. No unresolved financial obligation is evicted. Public health separates pending, abandoned and evicted unfinished maintenance; transfer records retain individual financial confirmations while retained.

For balance B, N recipients and current fee F, share=`floor((B-N*F)/N)` with checked subtraction/multiplication and minimum positive share of one e8s (a stake top-up, not neuron creation). All recipients receive the same net share. Dust is retained until plan completion for a later plan. The immutable plan binds roster, balance, initial fee, Ledger chain anchor, validated destinations and net amounts. Each attempt receives its persisted memo, fee and timestamp at first dispatch, not at plan creation; attempts after a verified no-execution rejection use a monotonically numbered memo. The existing rejection vector retains twelve recent exact conclusive-refusal identities; older conclusive-refusal details may be pruned. The current possibly executed identity and every retained payment confirmation remain exact. No hash archive is needed for recovery. There is one active plan. New deposits and roster changes do not enlarge or rebuild it.

Transfers move Prepared (no attempt) -> Unknown (persisted attempt before await) -> Verifying -> Confirmed, or Held; a verified first-dispatch no-execution refusal becomes Rejected and permits a new numbered attempt after fresh fee/funding checks. Twelve conclusive refusals exhaust one retry episode and enter a persisted one-day Cooldown; expiration permits another bounded episode after fresh preflight. Attempts remain monotonic across episodes and upgrades. A refusal on an already ambiguous retry cannot clear its earlier uncertainty. Both Ok and Duplicate block references must match exact authoritative Ledger transaction history before confirmation. Exact-identity retries are limited conservatively to 23 hours, inside the source's 24-hour window. After that, bounded replicated `query_blocks` and authoritative archive callbacks search from the plan's pre-send chain anchor. Absence never authorizes a replacement transfer. Unknown blocks, unavailable history and lag retain liabilities. Fee changes preserve original entitlements and prior confirmations. Remaining fees require explicit reservation from available funding; insufficient additional fees hold the plan. There is no partial-plan redistribution. Balance alone never proves payment. Block IDs cannot confirm two obligations.

The stable header pins the application policy revision, evaluator commit and protocol commit. A changed pin on upgrade invalidates unfinished computations and recipient drafts, advances the configuration revision and returns to ObserveOnly; dispatched following intents remain available for readback and financial obligations and any potentially executed identities remain intact (V1 records undergo the documented lossless obligation migration). Explicit upgrade arguments can activate a reviewed mode. State uses a versioned stable cell and lossless canonical Candid roundtrip checks, with a 64 MiB serialized-state cap. Every state transition flushes before await, including cursors and immutable financial intents. Job generations fence old callbacks, including lease replacement and upgrades; upgrade invalidates workers, keeps all obligations, converts proposal intents to ambiguous investigation, and rearms exactly one timer per job. Five independent jobs use bounded steps and bounded backoff; the fifth owns only best-effort recipient stake maintenance. Initial selection is weekly, proposal/staged-balance checks daily; active read work uses bounded one-second continuations in addition to ten-second fallback timers; irreversible financial operations retain separate durable dispatch/readback steps. This is not a guarantee of wall-clock completion.

Queries cap each page at 100 rows. The current scan, outcomes, scaled scores, planned/applied rosters, overlaps, proposal progress, payout/transfer references and cycle/job health are public. Completed payout detail is limited to 32 plans; unresolved obligations are never pruned. Score rows label whether a complete scan supports them. Controller/wallet data for private support neurons is not published.

The previous scoring hardening introduced policy `selection-2` and stable V2. This financial lifecycle tranche preserves that scoring policy and the Dendrite pin, and introduces stable V3 only for the necessary lifecycle fields/variants and independent maintenance job. Exact historical V1 and V2 wire envelopes have explicit lossless conversion. V2 Held attempts become safely retryable only when their persisted execution flag conclusively says no execution; reason strings never supply that proof. Historical ambiguous Held records remain ambiguous. See [the hardening contracts](hardening-design.md). RC1/RC2 qualification does not qualify V3.
